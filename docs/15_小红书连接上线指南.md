# 小红书连接服务上线指南

主应用（`huawei-pc-marketing-agent`）通过内部 MCP 服务（`cangyuyi/huawei-xhs-mcp`）读取小红书笔记。本文说明为什么云端扫码会“手机已确认但服务端没反应”，以及让它在线上正常可用的几种方式。

## 1. 现象与根因

- 现象：扫码后手机端完成确认，主应用弹窗仍停在“等待扫码”，`/api/v1/xhs/status` 一直 `logged_in=false`。
- 根因：MCP 运行在云机房 IP 上、且是无头浏览器，小红书会把它当成“新设备/高风险环境”，登录流程被要求 **短信验证码**。而 `xiaohongshu-mcp` 只有二维码登录接口，**没有提交短信验证码的接口**，所以流程无法完成。
- 次要原因：MCP 容器没有持久磁盘，重启/重新部署会清空 `/app/data/cookies.json`，已经登录的会话会丢失。

一句话：扫码登录在本地机器上通常没问题，在云机房 IP 上会被风控拦住。

## 2. 四种可选方案

| 方案 | 可用性 | 需要你做什么 | 风险 |
|---|---|---|---|
| A. Cookie 注入（推荐） | 线上可用，重启不丢 | 本地登录一次，把 `cookies.json` 配成 Secret | 会话放到服务端；建议用小号 |
| B. 本地 MCP + 隧道 | 线上可用，但依赖本机常开 | 本地常驻运行 MCP，暴露一个隧道地址 | 本机需开机；隧道地址可能变化 |
| C. 住宅代理 | 取决于代理质量 | 给 MCP 配 `XHS_PROXY` | 代理成本；不保证一定通过 |
| D. 公开热榜/编辑方向兜底 | 立即可用，非小红书实时 | 无需操作 | 不是实时笔记，界面已明确标注 |

下面的步骤按方案 A 写（已实现：MCP 镜像启动时会从 `XHS_COOKIES_JSON` Secret 恢复 `cookies.json`）。

## 3. 方案 A：Cookie 注入步骤

### 3.1 在本机登录一次（不会被云端风控）

```bash
git clone --depth 1 https://github.com/xpzouying/xiaohongshu-mcp
cd xiaohongshu-mcp
# 方式一：用官方登录程序（会打开浏览器，正常扫码/短信验证都能过）
#   下载 Releases 里的 xiaohongshu-login-<你的系统> 直接运行；
# 方式二：源码运行
go run cmd/login/main.go
```

登录成功后，cookie 会保存在仓库的 `data/cookies.json`（Windows 为 `data\cookies.json`）。确认文件里有 `web_session` 等字段。

### 3.2 写入魔搭 Secret

1. 打开 `https://www.modelscope.cn/studios/cangyuyi/huawei-xhs-mcp` → 设置 / Secrets；
2. 新增或更新变量 `XHS_COOKIES_JSON`，值就是 `cookies.json` 的**完整内容**（单行 JSON）；
3. 重启创空间（或重新部署）。启动日志里会打印：
   `[entrypoint] cookies.json restored from XHS_COOKIES_JSON (… bytes)`。

### 3.3 验证

```bash
# MCP 直连（需要 ModelScope access key）
curl -s -H "Authorization: Bearer $MODELSCOPE_ACCESS_KEY" \
  https://studio-cangyuyi-huawei-xhs-mcp.api-inference.modelscope.net/api/v1/login/status
# 期望：{"success":true,"data":{"is_logged_in":true}, ...}

# 主应用
curl -s -H "Authorization: Bearer $MODELSCOPE_ACCESS_KEY" \
  https://studio-cangyuyi-huawei-pc-marketing-agent.api-inference.modelscope.net/api/v1/xhs/status
# 期望：{"status":"ok","configured":true,"logged_in":true}
```

然后在主应用左侧「热点搜索」里刷新，就能看到实时笔记（标题、链接、点赞数）。

## 4. 方案 B：本地 MCP + 隧道

如果你不希望把会话放到云端：

```bash
cd xiaohongshu-mcp
go run cmd/login/main.go          # 本机登录
go run . -headless=true -port=0.0.0.0:18060
# 另开一个终端，做临时隧道（示例）
ssh -R 80:localhost:18060 nokey@localhost.run
```

把主应用环境变量 `XHS_MCP_BASE` 改成隧道地址、`XHS_MCP_TOKEN` 保持服务端令牌，重启主应用即可。注意本机需要保持开机，隧道地址变化后要同步更新。

## 5. 安全与合规

- 只使用**自有或明确授权**的账号；公开演示建议用小号，不要把主账号登进公开实例。
- `XHS_COOKIES_JSON` 只放在魔搭 Secrets，不进仓库、不进日志、不下发前端；如果会话曾经出现在聊天/截图里，请重新登录并替换。
- MCP 的写操作（发布）当前未启用；主应用只做只读搜索与热点参考。
- 登录失效、遇到验证码或风控时，主应用会暂停读取并回退到公开热榜/编辑方向，不会假装成功。

## 6. 常见问题

| 问题 | 处理 |
|---|---|
| 扫码后手机确认，服务端仍 `logged_in=false` | 云端风控；改用方案 A/B |
| `is_logged_in=true` 但搜索为空 | 关键词过窄或账号权限受限；换关键词/稍后重试 |
| 重启后登录丢失 | 重新写入 `XHS_COOKIES_JSON`（方案 A 会自动恢复，需确认 Secret 还在） |
| 热点搜索显示“编辑方向” | 未登录或来源不可用，属预期兜底；登录后刷新 |
