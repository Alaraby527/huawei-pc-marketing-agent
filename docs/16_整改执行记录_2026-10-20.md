## 0.15.0 引导式对话（2026-10-20 追加）

用户反馈“原始 JSON 漏到界面、流程不像正常对话”，当前默认 UI 已改为引导式：

1. 先了解人群和用途；只问会改变结果的问题，选项可点也可自由输入。
2. 从知识库推荐 3 款真实型号，每款给出与需求相关的 2–3 条事实和选择理由。
3. 用户选一款后，先确认发布方案（平台、页数、语气、使用知识库原图），再开始生成。
4. 生成推文时只挑 3–6 条与叙事最相关的参数，不把全部规格塞进文案；所有数字仍走字段级事实检查。
5. 图片直接返回知识库里该型号的原图，不重画产品外观；随后询问“都保留 / 重新生成文案 / 重新生成图片 / 改某一页”。
6. 流程是软的：用户直接点名型号可跳过推荐；说“你定”可跳过追问；在中途换产品、改页数、改风格、只改某一页都能接住。

本地真实 DeepSeek 验证：问候 → 大学生 → 校园学习 → 3 款候选 → 选第 1 款 → 确认 6 页方案 → 6 页文案 + 4 张知识库原图 → 重新生成图片（换一组原图）→ 重新生成文案（v3）→ 都保留；另测“给 MateBook 14 写 3 页”直接进入方案确认，生成 3 页 + 4 张原图。事实检查通过，原始 JSON 不再出现在聊天中。

线上复验（2026-10-20，ModelScope v0.15.0）：同一链路在 `https://cangyuyi-huawei-pc-marketing-agent.ms.show/` 通过。问候返回干净文本和 4 个可点选项；“大学生，校园学习”正确进入选品而不是重复问候；推荐 3 款真实型号；“第 1 款”进入方案确认；“开始生成”交付 6 页 + 4 张原图，事实检查通过；“都保留”进入定稿。期间修复了“把用户回答误判为打招呼”的分支，并重新部署。

**尚未完成人工审稿**：`effect_reviewed=false`，需要用户实际使用后确认自然度、需求贴合和实用性；`production_ready=false`，发布能力保持关闭。

## 真实主模型验证（2026-10-20）

模型：`deepseek-v4.1-flash`，端点 `https://maas.qianwenaiapi.com/compatible-mode/v1`，原生 `tools` 协议，本地知识库 `official-kb-v7.zip`（`KB_SOURCE=local`）。未使用线上实例、未修改线上 Secrets/数据库。

> 说明：中途发现旧测试服务的 `LLM_MODEL` 实际是 `qwen-plus`。qwen-plus 在该网关出现过单次调用挂起 15 分钟、反复使用自造型号 ID 的情况，相关早期样本已作废；下表只统计显式配置 DeepSeek 后的结果。

|---|---|---|
| A 明确需求直做 | MateBook 14、大学新生、轻松、不写价格、3 页；25.7 秒完成，3 页，`check.passed=true`；未追问预算/地区，未重新选型 | 通过（1/1） |
| B 模糊需求 | “想做点电脑内容，不知道写什么”；返回 `waiting_user` 并问“更想围绕哪类电脑内容来做？” | 通过（1/1） |
| C 只改第二页 | 两次样本（8.1–12.4 秒）：生成 v2，仅第 2 页文本变化，其他页逐字一致，`fact_ids` 与事实限定保留，`check.passed=true` | 通过（2/2） |
| D 参数造假 | 要求“内存写成 64GB”：交付物均未出现 64GB，正文使用真实值 24 GB / 32 GB；明确说明未照做。模型两次拒绝改写后，后端按字段真实值清洗并重新检查通过 | 通过（最终修复后 2/2；早期 4 次为诊断样本，已由重试+清洗修复） |

| F 暂停/重启恢复 | 模糊需求进入 `waiting_user`；重启服务后同一会话恢复；回答“给大学生写 MateBook 14，3 页”后完成交付，`check.passed=true` | 通过（1/1） |
| G 你来定 | “你来定，先给我一版”；未继续追问，采用 6 页校园向方案直接交付，并说明页数是可调整假设，`check.passed=true` | 通过（1/1） |
| H 可变页数 | 要求 6 页：3 次样本全部输出 6 个独立 `pages`，无价格，`check.passed=true`；另有 3 页（A/C/F）与 1 页请求验证 | 通过（6 页 3/3） |

修复过程记录：

- 原生工具 schema 需要 `{"type":"function","function":{...}}` 包装；修正后 DeepSeek 与 qwen-max 均能返回 `tool_calls`。
- 模型在拿到证据后曾反复 `search_products`；增加工具目录提示、重复调用保护、自动续接证据，并在证据就绪后执行一次受控创作调用。
- 搜索曾用 `any(term in model)`，导致“MateBook X Pro 2027”命中所有 MateBook；改为按型号特征词（数字、pro、fold 等）匹配，未知型号返回 0 命中并提示不要编造。
- 字段核对曾因“厚度/刷新率”等字段别名误报；已按 `_FIELD_ALIASES` 归并，并为每个数值出现位置建立事实记录。
- 模型声称“6 页”但只输出 1 页；现校验 `pages` 数量，不符时重写一次，仍不符则不保存并如实说明。
- 参数造假曾出现两种失败：模型坚持写 64GB 导致检查失败、或直接不交付；现最多重试 2 次，仍失败时后端只替换未证实的数值为同字段真实值，再检查保存，并在回复中说明。
- 网关可能长时间不返回；文本模型请求增加总时限（默认 120 秒，测试用 90 秒）和整轮预算（默认 180 秒），避免单轮无限等待。
