# 配方测试图（展示版）

本目录是**风格配方库（R01–R24）逐张生成样图**的展示副本，用于评审时对照"配方到底生成了什么"。

## 这些图是怎么来的

```
知识库核验产品原图（HUAWEI MateBook 14 原野绿正面展示，image_id I-9f9470747d7e3c40）
        ↓  作为参考图送入图像通道（图生图，img2img）
   配方提示词（R01–R24 各自的 composed_prompt）
        ↓
   生成图（kind = generated_scene，不是产品实拍）
```

- **只有图生图这一条路**：产品原图 + 提示词 → 新图。不提供纯文生图、背景合成等其它模式。
- 每张提示词末尾都带产品条款：写实类严格执行"产品要求和原图中的产品一致，大小比例logo外观保持不变"；
  风格化类（黏土/像素/纸艺/波普/微缩/拼贴/套印/超现实/几何 共 9 个）允许按风格重绘，
  但要求仍是同一款产品、型号特征与 logo 位置一致、不得出现替代商品。

## 验收结果（人工逐张）

| 状态 | 数量 | 说明 |
|---|---|---|
| **已批准** | **22** | 项目负责人逐张验收通过，可进生成链路 |
| **已剔除** | **2** | R04 水墨空间、R22 文字主视觉 —— 两张都丢了产品本体 |

**批准是一份记录，不是改字段**：`app/data/recipes/releases.json` 存具名审批人、审批时间与
**逐张 sha256 证据**；配方 JSON 文件本身仍标为 `unverified_real_images`，因为"把字段改成 approved"
不等于生产批准。

因此本目录里的 R04、R22 **也一并保留**——它们是"我们剔除了什么、为什么剔除"的证据。

## ⚠️ 三个必须说清的点

1. **本目录是压缩后的展示副本，不是 sha256 证据原件。**
   原始 PNG 共 51.6 MB，为控制仓库体积压缩为约 1.8 MB（宽 720px、JPEG q82）。
   `releases.json` 里的 sha256 对应的是**原始文件**，不要用这里的图去核对哈希。

2. **这些是生成图，不是产品实拍。**
   `kind = generated_scene`。画面上的产品由模型按参考图重绘，**不得用于证明产品外观、
   不得当作所选配置的实拍**。

3. **产品图片的版权归原权利人。**
   参考原图来自项目联调知识库（官方知识库 v7 本地导出），仅用于项目展示与效果评估，
   不构成产品官方素材。

R<编号>_<配方名>.jpg        # 该配方的成图
