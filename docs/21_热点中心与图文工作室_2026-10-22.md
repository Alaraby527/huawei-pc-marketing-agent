# 热点中心与图文工作室（2026-10-22）

本轮按用户确认的四项决定落地三套方案，原有架构与功能不变，只增新功能。

## 一 图文工作室：用户驱动的另一半

用户描述的实际流程：

```
对话 → 生成文案 → 带出知识库原图 → 用户选择：
   ├─ 去图文工作室 → 工作室里自己生图、自己改文案
   └─ 直接改文案
```

- 入口在交付物卡片上，叫 **“去图文工作室 →”**，携带 `?conversation=<id>`，所以**固定产品与本次创作的粗略信息自动带过去**，不需要重打。
- 页面 `/studio/workbench`：知识库核验原图（可选中作参考）、文案结构化编辑（标题 + 逐页）、生图（提示词/比例/尺寸）。
- **改文案走 agent 自己的 `_save_artifact`**：同一套事实检查、同一套版本号、同一个 STALE_REVISION 防覆盖。人工改稿不得绕过核验。
- 生图产物 `kind = "generated_scene"` 并带固定标注：**不是产品实物照**。

实测（真实接口、真实知识库）：

| 环节 | 结果 |
|---|---|
| 文案生成 | 真实文案，“已通过事实检查（0 错误、0 警告）” |
| 产品继承 | MateBook 14（鸿蒙版）自动带出 |
| 知识库原图 | 4 张核验原图 |
| 改文案写错参数（64 GB） | **拒绝** `FACT_CHECK_FAILED` / HTTP 409，“知识库中找不到 64 GB 对应的事实” |
| 改文案正确内容 | 存入同一产物第 3 版，无分叉 |
| 生图 | 30–74 秒成功，参考图 `I-9f9470747d7e3c40`，能力 `verified_yes` |

## 二 图生图能力与探针证据

- 可用形态：`POST /v1/images/generations` + `image` 传 data URL；模型 **`gpt-image-2.5`**。
- `gpt-image-2-w` 对**带图**请求稳定 503（不带图正常）→ 能力按 `(模型, 是否带参考图)` 分别登记，未探测的组合一律 `unverified`，**不写 true**。
- `/images/edits`（multipart）90 秒读取超时无响应 → 按登记表**跳过该尝试**，每张图省约 90 秒。
- 尺寸 `1080x1440` 被接受，但**实际返回 1086x1448**（约 +0.55%），排版必须按实际尺寸适配。
- 保真度如实说明：机型/配色/圆键/壁纸保持，**机身比例、视角与按键排布是重绘的**（正面参考图会返回 3/4 透视）→ 不得作为外观、接口、键盘布局的依据。
- 完整探针记录见 `docs/20_图像能力探针记录_2026-10-22.md`。

## 三 热点中心：应用内模块（非生产形态）

按用户决定做成现有应用内模块：契约照方案（10 个 `/api/hotspots` 操作），数据用 SQLite，
并**在每个响应上标注 `production_ready: false`**。

- 六个候选来源全部 `enabled=false, approval_status="pending"`（方案模板即如此，是安全设计）：refresh 返回 `no_work`，榜单返回 `no_approved_sources`。
- **六时间分离**；未真正访问原平台的抓取记 `cache_only` 且**不推进 `verified_upstream_at`**（“HTTP 200 只能证明响应成功”）；`stale_fallback` 记 `failed`。
- **同源不重复计票**：两个 provider 服务同一原平台只算一票（按 `hs_sources.origin_platform` 映射，而非 `source_id`）。
- 保守聚合、原子发布、幂等三态、租户与用户隔离、风险内容不入场景榜。
- **未验证**：NewsNow、PostgreSQL、并发/发布事务（方案明说“SQLite 或内存 mock 不能替代”）；本机无 Docker/PG，这些**不作为已验证能力**。

## 四 surface 与 platform 分离

- 现有 `Platform` 枚举**未改**，新增交付面层承载 `personal_moments` / `store_moments` / `work_account`。
- 本项目 `moments` 的名称是**门店朋友圈**，对应包3 的 `store_moments`；包3 的 `personal_moments` 才是新增面。
- **`work_account` 的 `platform` 为空**：包1 明确“含义未确认…禁止假设为公众号”，故携带未决问题而不猜。
- 包3 与本项目旧 `PLATFORM_RULES` 的字数冲突记录在 `SPEC_CONFLICTS`，**不静默覆盖**（改字数等于悄悄改行为）。

## 五 方法库与占位符硬门槛

- 20 条方法全部落地，`route` **连同原因返回被排除的方法**，并把本系统无法自造的证据（价格、活动条款、真实案例、授权、服务政策）标为不可验证。
- 占位符：包3 的 `no_unresolved_placeholders` 是硬门槛，而我们此前只能靠运气发现。15 个必拦样例 + 8 个不得误拦样例参数化测试；只标记并置 `partial`，不改写。

## 六 成本账本

- 提交付费尝试**前**预留预算；结算为实耗或释放；**无法估算即阻断提交**；**unknown 进对账、不清零**；同一请求共享一个上限（来自服务端环境变量）。
- **一处刻意且可见的偏离**：方案要求预算未配置前禁止计费，严格说等于拦截。默认**不拦**（`IMAGE_BILLING_ENFORCE=1` 才拦），因为你正在用它验收；期间每次调用仍记为 `unpriced`，未授权花费不会被当成已入账。
