## 当前实现与边界

前段完成：需求槽位/可选自然语言解析、缺失项追问、型号候选、精确型号确认、场景/平台策略、ima搜索、目录回退、原文读取、事实与脚注提取、同型号图片筛选和实际读取、风险及状态交接、CLI导出。无须大模型密钥，不依赖前端。

真实联调库：`Alaraby的知识库`。这是用户指定的个人库，始终标记`official_library=false`、`competition_ready=false`。赛事指定库`任德耀新建华为PC知识库`目前无法加入，因此未验证；不应在作品说明书宣称已完成指定库接入。设置`IMA_KB_NAME`可切换，接口和材料协议不变。

还没有完成：逐条语义事实核验、生成图片/海报的正式排版合成、云端部署与主办方库权限验证、面向公网的鉴权/限流与多 worker 会话存储。对话链路的`can_publish=true`只表示草稿已绑定当前材料、规则扫描通过且运营人员确认，不等于法律合规保证。

## 最快试用

本机双击项目根目录的`测试前段导购.command`。逐项输入型号、人群、场景、目标与平台，回车采用示例值。结果JSON在`.runtime/last-handoff.json`，图片在同目录`assets/`。也可运行：

```bash
.venv/bin/python scripts/guide.py libraries
```

## HTTP接口

本次测试服务基址`http://127.0.0.1:7861`；该地址仅本机可访问。队友异机调用需将同一代码部署到其后端，或由你共享本地导出包；不能把127.0.0.1当双方共用地址。

| 接口 | 行为 |
|---|---|
| GET `/healthz` | 进程健康 |
| GET `/api/v1/readiness` | 配置存在与实现状态，不冒充真实权限验证 |
| GET `/api/v1/knowledge/libraries` | 实际读取当前凭证可见库名，不暴露库ID |
| GET `/api/v1/knowledge/connection` | 实际连接已配置知识库，返回名称、连接状态、是否赛事库 |
| POST `/api/v1/guide` | 前段主入口，支持部分输入和材料交接 |
| GET `/api/v1/assets/{token}` | 读取本次检索缓存图片，过期410 |
| GET `/api/v1/contracts/materials` | 原有MaterialBundle 1.0 JSON Schema |
| POST `/api/v1/materials/validate` | 结构与材料完整度预检查，不声称语义真实或可发布 |
| POST `/api/v1/tasks` | 保留503后段待接入分支，会调用前段，但不生成终稿 |

```bash
curl -X POST http://127.0.0.1:7861/api/v1/guide -H 'Content-Type: application/json' --data-binary @examples/task.personal.json
curl -X POST http://127.0.0.1:7861/api/v1/guide -H 'Content-Type: application/json' -d '{"message":"给大学新生写HUAWEI MateBook 14（鸿蒙版）的开学朋友圈，邀请到店体验"}'
curl -X POST http://127.0.0.1:7861/api/v1/guide -H 'Content-Type: application/json' -d '{"message":"想买轻薄本"}'
```

完整输入字段：`product_query`、`audience`、`scenario`、`objective`、`platform`；可选`purchase_stage`、`instructions`、`message`。platform为`moments`、`wechat_article`、`xiaohongshu`、`poster`。已有明确字段优先于message解析。解析是有限规则，识别不了时追问；不依赖模型猜测。

购买阶段可保持待确认；预算不强制用于每篇营销任务。“想买轻薄本”不会直接编一个型号；返回下一问和完整缺失列表，调用方回传已收集槽位。泛化型号在完整任务下可进入真实候选检索，但须确认准确产品后再生成。

## 给队友的数据

主入口返回外层交接信封，`materials`严格沿用现有`MaterialBundle v1.0`，无破坏性字段变动。原有消费者可直接读取`result['materials']`；内容策略等增量读取外层。

| 字段组 | 路径与含义 |
|---|---|
| 任务上下文 | `materials.task`含产品、人群、场景、目标、平台、阶段、补充要求；`request_id`唯一标识 |
| 产品身份 | `materials.product`含稳定产品ID、标准型号、配置边界和确认状态 |
| 可用事实 | `materials.facts`每条含稳定事实ID、产品ID、完整规格章节、条件、资料标题、证据定位和原文片段 |
| 可用图片 | `materials.images`每条含ID、产品ID、读取地址、说明、来源和型号核实状态；`image_plan`建议插入位置与用途 |
| 风险与缺口 | `materials.issues`、`risks`、`questions`、`guidance.unknowns`；价格权益无当日证据时标记删除/待核实 |
| 数据状态 | `data_state.read_at`是本次读取UTC时间；资料自身抓取日期仍在证据条件里，不能混同；状态/原因及`trace`保留真实步骤 |
| 场景策略 | `strategy`含切入点、用户问题、事实优先顺序、平台结构/语气/篇幅建议/CTA和禁止断言 |
| 导购结果 | `guidance`给出重点事实ID、后续核对动作与未知项；`candidates`是检索发现的候选，不代表都适合或都有现价 |
| 交付门槛 | `can_generate`仅表示前段材料完整；`competition_ready`仅表示来源门槛与材料完整，不代表作品完成；`can_publish`在前段固定false |

`materials.status`：ready可进入后段；needs_input追问或缺图/缺资料；conflict停止生成并人工核对；unavailable为权限、网络、原文或超时错误。HTTP业务状态放在JSON内，格式错误422，图片过期410。

## 队友如何接入

```python
from app.intake import Intake
from app.retrieval import guide

result = await guide(Intake(**task_fields))
if not result['can_generate']:
    # 将questions或materials.issues呈现给调用方，补充后重新请求。
    return result
bundle = result['materials']
strategy = result['strategy']
# 在这里调用队友的生成器，使用bundle中的事实与图片，遵守strategy与risks。
# 生成后逐条核验断言、图片与宣传表达，再决定是否交付；不能直接把can_publish改成true。
```

完整系统约束在`prompts/agent-system.md`。前段使用确定性Python工作流，因此未把提示词伪装成正在运行的LLM调用；队友后段应实际加载其约束。

HTTP图片地址是相对基址，已下载缓存且不需要把ima认证头交给队友；同进程可用HTTP读取。图片缓存30分钟、最多60份/80MB，单图8MB；重启/过期/缓存淘汰后重新检索。CLI进程会退出，所以自动将图片写入本地assets并替换为绝对文件路径；传给异机需一起复制图片并重映射路径。HTTP与CLI两种交接不能混淆。

## 有意保留的限制

- 目前自动读取Markdown/TXT/HTML文本；需要`# 型号 - 产品事实`及支持的`##`规格章节。PDF/Word、ima笔记等未自动解析，明确返回补充或不可用，不假装读过。发现卡、价格卡和历史商城快照不升级为完整事实；当前资料提取适配了已实际读取的个人库结构。
- 产品确认是型号级，非销售SKU级。标准/柔光、圆/方键盘和不同容量保留分支，不任意拼成一个配置，也不宣称已完成颜色/SKU认证。
- 同一完整事实来源集内同章节不同内容会停止交付；不同章节、发现卡、历史快照之间的语义冲突尚不自动穷尽，后段必须继续检查。不会因没发现冲突就宣称所有资料一致。
- 图片核验是ima文件名与规格来源中的官方产品slug严格匹配、实际下载和PNG/JPEG/WebP签名核验；没有视觉模型或人工像素鉴定。不用其他型号凑图，不从文件名或图像推断性能。
- 不自动承诺软件兼容、续航时长、价格、补贴、库存、售后条款或预算内可购。没有这些证据时只输出待确认项与到店验证建议。
- 规则解析覆盖常见任务，不能取代任意语义理解。场景以用户明确人群和场景决定，额外指令不覆盖已确认的场景。
- API单次ima子调用30秒、素材读取15秒、前段总限150秒；无数据库和后台队列，当前单进程MVP。公开部署还需鉴权与配额保护，默认在本机监听即可测试。
- 当前凭证能证明读取权限；官方接口未返回完整个人登录身份，不能把库创建者冒充凭证使用者。提供真实连接状态而不假称账号实名识别已完成。

## 验收建议

1. `connection`确认个人库真实连接；不回显密钥。
2. `task.personal.json`取得13组规格和当前平台要求的实际图片；打开素材抽查对应型号。
3. 改人群/场景：学习携带转创作，观察angle、事实优先级和选图排序变化。
4. 改平台：朋友圈转公众号/小红书/海报，观察结构、语气、CTA和图片数变化。
5. 泛化/相近型号、缺项、没有来源的价格、冲突、失效图片触发追问/拦截。
6. 队友生成完整图文并逐项核验后，才能把该结果写进初赛优秀运行结果；当前前段包是联调证据。
