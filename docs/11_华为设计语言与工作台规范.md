# 华为设计语言与 PC 工作台规范

本文用于说明本项目为什么采用当前的视觉与交互，以及哪些数值来自官方 HarmonyOS Design 文档。目标不是“给聊天网页换华为蓝”，而是把工作台做成 **HarmonyOS 的 PC 效率应用**。

## 1. 设计理念

官方 HarmonyOS Design 的核心是 **One / Harmonious / Universe**，中文常概括为“万物归一、回归本源、平衡共生”。落到工作台：

1. **一个任务、一个空间**：对话、六页画布、证据不是三个产品，而是同一任务的不同视图。
2. **平衡而非堆叠**：左右分栏保持稳定重心，卡片、留白、对齐线形成秩序。
3. **少层级、一个主动作**：每屏只保留一个主任务和一个主按钮，次要操作收入底部或菜单。
4. **卡片承载信息单元**：候选型号、六页内容、证据、确认门都用卡片表达，不在卡片里塞流程。
5. **证据常驻**：每个结论都应能回到来源；右侧证据区是常驻的，不是隐藏页。
6. **确认门分级**：低风险内联提示，中风险内联确认，高风险/对外发布才使用强打断确认。
7. **PC 不是手机放大版**：≥840vp 使用侧边/三分栏，控件更紧凑，圆角比移动端小。
8. **可感知、可控制、可反悔**：发布前必须有人工确认；需求、证据变化会作废旧稿；关键操作有明确状态。

## 2. 色彩 Token

官方 HarmonyOS 色彩体系以“宇宙蓝 + 雪域灰”为基础。本项目使用以下 token（浅色）：

| Token | 值 | 用途 |
|---|---|---|
| `brand` | `#0A59F7` | 主操作、焦点、强调 |
| `brand_hover` | `#317AF7` | 悬停/深色主题品牌色 |
| `warning` | `#ED6F21` | 待核实、提醒 |
| `danger` | `#E84026` | 阻止、危险、不可逆 |
| `confirm` | `#64BB5C` | 通过、成功 |
| `text_primary` | `rgba(0,0,0,.90)` | 正文主色 |
| `text_secondary` | `rgba(0,0,0,.60)` | 说明文本 |
| `text_tertiary` | `rgba(0,0,0,.40)` | 辅助信息 |
| `bg_primary` | `#FFFFFF` | 页面/组件一级背景 |
| `bg_secondary` | `#F1F3F5` | 页面二级背景 |
| `comp_divider` | `rgba(0,0,0,.08)` | 分割线 |

使用规则：

- `brand` 只用于强调，不做大面积底色。
- 正文与背景对比度 ≥ 4.5:1；大字号/图标 ≥ 3:1。
- 层级优先用灰阶和间距表达，阴影只做辅助。
- 深色模式用明度表达层级，页面背景保持不透明。

## 3. 字体与排版

- 字体：**HarmonyOS Sans**（鸿蒙黑体）；Web 回退 `system-ui → PingFang SC → Noto Sans SC`。
- PC 字号参考：Display 36/46/54vp，Title 18/22/28vp，Subtitle 12/14/16vp，Body 14vp，Caption 9/12vp。
- 一个页面文本样式不宜超过 3 种；默认左对齐；中文单行建议 ≤ 52 字。
- 本项目：正文 14px / 行高 1.6；标题 16–22px；说明 11–12px。

> HarmonyOS Sans 用于 Web 嵌入前应确认字体授权与分发条款；本项目不打包字体文件，仅使用系统回退。

## 4. 间距、圆角与栅格

官方以 **8vp 为基础网格**，4vp 为子网格。

| 项 | 官方/落地值 |
|---|---|
| 基础网格 | 8vp |
| PC 屏幕边缘 | 40vp（本项目 16–24px 响应式） |
| 卡片间距 | 12vp |
| 控件间距 | 8/16vp |
| 栅格 | 0–600vp 4 列；600–840vp 8 列；≥840vp 12 列 |
| 内容最大宽度 | 2220vp；单行中文 ≤ 52 字 |
| 圆角 | 4（标签）/8（图片、小容器）/16（卡片）/20（按钮、菜单）/32（弹窗） |
| PC 圆角 | 比移动端更小：按钮 8–10px，卡片 12–16px，弹窗 16–24px |

本项目工作台：卡片 12–16px，按钮 10px，标签胶囊 999px，页面 8px 网格对齐。

## 5. 动效

| 场景 | 时长 | 曲线 |
|---|---|---|
| 颜色/状态变化 | 100ms | 标准 |
| 开关/小范围运动 | 150ms | 标准 |
| 列表删除 | 200ms | 标准 |
| 短距离运动 | ≤250ms | 标准 |
| 全屏转场 | ≤350ms | 标准/减速 |

- 标准曲线：`cubic-bezier(0.40, 0.00, 0.20, 1.00)`。
- 弹性曲线适合跟手、可打断、可继承速度的场景；常规 UI 不应全部使用弹簧。
- 一屏同时只有一个核心动效；尊重 `prefers-reduced-motion`。
- 本项目：消息出现 180ms，toast 180ms，按钮/悬停 150ms，不使用阻塞式全屏 loading。

## 6. 工作台结构映射

| HarmonyOS 原则 | 本项目落地 |
|---|---|
| PC 三分栏 | 320–360px 对话 + 自适应画布 + 300–340px 证据 |
| 顶部步骤条 | 需求澄清 → 选品确认 → 内容生成 → 人工核验 → 导出交付 |
| 卡片化 | 候选卡、六页卡、证据卡、草稿卡、确认摘要 |
| 核心操作栏 | 底部状态栏 + 草稿卡操作区 |
| 一镜到底 | 聊天产物 → 候选卡 → 六页画布；共享容器/状态切换 |
| 证据常驻 | 右侧事实、图片、知识库状态；小屏切换为“证据”标签 |
| 分级确认 | 产品选择 / 成稿确认两道门；导出只在确认后出现 |
| 空状态 | 说明“为什么空 + 下一步”，提供示例入口，不用假数据 |

## 7. 反模式（本项目避免）

1. 把手机单列 UI 直接拉到 PC。
2. 卡片套卡片、圆角/阴影泛滥。
3. 每一步都弹模态框。
4. 低对比度、整页半透明、纯黑纯白跳变。
5. 超长行宽、超大图片、过多留白。
6. 热区过小、纯图标、仅 hover 可见。
7. 动效过多、过长、不可打断。
8. 隐藏不确定性、自动执行不可发布操作、卡片内做流程。
