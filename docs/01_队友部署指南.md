# 队友部署指南

## 1. 先确认部署到哪个账号

已创建的空间：`cangyuyi/huawei-pc-marketing-agent`，中文名称“华为PC营销图文工作台”，当前非公开、未完成首次部署。部署负责人：王泽栋。

空间页面：

```text
https://www.modelscope.cn/studios/cangyuyi/huawei-pc-marketing-agent
```

这是项目页面，不是已经运行的独立应用地址。

### 路线A：队友在自己的账号部署

适合立即开展协作。队友登录自己的魔搭账号，创建自己的开发创空间，再上传同一份项目。拥有者独立管理凭证与资源，完成后把其空间地址和测试结果发给项目负责人。你们不必共享密码。

### 路线B：在同一个团队空间部署

如果最终要两人共同管理一个线上作品，使用魔搭支持的团队/组织权限流程分配访问与部署权限。当前空间属于个人账号，单纯把私有空间链接发给队友不会授予访问权。需要先由拥有者在平台确认可用协作方式；本次未添加成员、创建组织或改变权限。

当前已创建空间也可由拥有者部署，队友提供代码和排障支持。

## 2. 解压与本地验证

解压交接包后，先阅读根目录README，按对应系统的命令启动。确认首页、健康检查、接口文档和材料包校验可用。

`requirements.lock`锁定的是当前已验证运行环境的依赖版本。开发测试依赖另见`requirements-dev.txt`。

## 3. 上传空间文件

已创建空间当前页面提供：内容 → 首次部署引导 → 空间文件 → 选择文件，或拖入项目文件夹；同时提供通过Git上传入口。

上传根目录中的Dockerfile、requirements.txt、requirements.lock、app目录与README，保留`app/static`等子目录结构。不要把外层同名文件夹多套一层，确保部署根目录能看到Dockerfile。

开发环境`.venv`、缓存、真实`.env`、密钥、运行日志和原始知识库资料不包含在交接压缩包里，也不应上传。

建议双方建立共同Git仓库后通过版本管理更新文件；本次未创建GitHub仓库，也未给队友发送任何消息。

## 4. 首次部署设置

在上传后的部署设置中选择支持Dockerfile的运行方式。官方指南要求服务监听`0.0.0.0:7860`，本项目已经按该端口配置。

资源方案、账号绑定、实名认证和具体可用额度以实际控制台为准。没有模型本地推理需求时，先验证应用服务和外部接口链路，再决定资源配置。本交接包不包含任何付费订购。

先运行底座不需要填真实ima或模型密钥。它应正常打开，并明确显示业务尚未接入。

如果平台要求补充配置文件，按当前控制台的实际字段生成，并把验证成功的配置补回仓库；包内未猜测生成平台专有部署JSON。

## 5. 配置外部服务

第一部分接入时，配置ima账号凭证。第二部分接入模型时，配置服务地址、模型标识和密钥。敏感值使用平台Secrets，仅由实际配置人输入；不要通过聊天截图传播。

不要仅因填写了变量就宣布接口可用。必须分别执行知识库读取、图片访问、模型调用的真实检查。

## 6. 部署后验证

1. 检查构建与运行日志，确认应用启动成功。
2. 打开应用实际运行地址，确认首页可访问。
3. 在运行地址后访问`/healthz`，应返回`status=ok`。
4. 访问`/api/v1/readiness`，当前应显示`business_ready=false`。
5. 首页载入开发样例、检查材料包，应明确返回缺口与不可发布状态。
6. 可使用`python scripts/preflight.py <应用运行地址>`检查；不要把魔搭外层项目页当作后端API根地址。

如果应用通过魔搭页面内嵌展示，从控制台提供的实际运行入口或独立体验入口取得应用地址。本次尚未启动云端构建，不能提前给出一个声称可访问的运行域名。

## 7. 给项目负责人回传什么

- 空间所属账号/团队与空间页面地址。
- 实际应用运行地址。
- 部署代码版本或压缩包校验值。
- 首页截图和`/healthz`结果。
- readiness结果：服务是否可用、哪些业务尚未接入。
- 构建失败时提供已检查不含密钥的错误摘要。

此时完成的是部署底座验收，真实业务验收还要按下一份文档执行。
