# 新对话流程规格（用户口述整理 · 2026-10-23）

> 本文件是**用户确认过的需求规格**，实现以本文件为准。
> 凡本文件与旧实现冲突处，**以本文件为准**。

## 0. 最终产物（一次任务）

```
3 篇文案（可直接复制粘贴发小红书）+ 1 张知识库产品原图
```

用户拿到后**两个出路**：

| 出路 | 行为 |
|---|---|
| ①「图文工作室」按钮 | 把**选中的那篇文案 + 对应的知识库原图**全部自动导入图文工作室；**剩下的创作在工作室里完成** |
| ②「一键导出」按钮 | 下载【选中的文案 + 对应的知识库原图】，让用户直接去发布 |

**两个按钮都放在图片的最下方。**

**要删掉的东西**：原来的「小红书图文方案 · 7 页」（六页图文 / `render_visuals` / 页面卡片 / 长图 ZIP 下载）
—— 用户明确"整个删掉"。

## 1. 流程（默认走这套，但**不是定死的**）

```
① 先收四件事：目标人群 / 发布平台 / 使用环境·场景 / 要打的活动
   ——【不问型号】：用户不了解型号，让他先描述他要解决的事
        ↓
② 拿这四件事去知识库匹配 → 给出几款候选型号（2–4 款）
        ↓
③ 用户选型号：选 1 款或 2 款都可以
        ↓
④ 结合【四件事 + 选定型号的真实参数 + 任务资料里的热点】写作
        ↓
⑤ 产出 3 篇有差异度的文案（方向由模型自定）+ 该型号的知识库原图
        ↓
⑥ 图片最下方：【图文工作室】 + 【一键导出】
```

## 2. 任务资料（可累加的档案）

贯穿全程：**人群 / 平台 / 环境 / 活动 / 选定型号 / 参考进对话的热点**，
构成"**本次任务的资料**"。

- 用户**中途补充信息 → 并进资料**，后续产出都带着它
- **用户为主导**：用户跑偏了就帮他拉回来；合理的补充吸收进资料
- 流程只是**大框架**，用户可以自由回答、打断、补充

## 3. 信息收完时的确认

当我们认为资料已齐，**只出一句很短的话**确认是否交付，例如：

> 是否输出最后交付内容？

下面给**一个选项卡**（如「输出最后交付内容」）。
**用户也可以自由回答**（如"不行，还要补点信息"）——**以用户意思为主导**。

## 4. 三篇文案的选项卡交互

- 三个选项卡**不大**，合理分布在对话区里
- **单击 = 选中**（要有明确的选中态 / "变身"感）
- **双击 = 放大**，能看清整篇文案；放大态带**关闭按钮**，关闭回到紧凑态
- ⚠️ **实现注意**：双击浏览器一定会先触发一次单击。必须防误选——
  单击后延迟（约 250ms）再执行选中；若期间收到双击则**取消选中**、直接放大。

## 5. 型号多选时的分配

选 2 款时，**3 篇里混着**（例如 2 篇写 A、1 篇写 B）。不是每款一篇。

## 6. 热点的两种用法

| 方式 | 流程 |
|---|---|
| **主动参考（主路径）** | 用户先在**热点榜**选中一个热点 → 点「**参考到对话**」→ 热点**进入对话** → **补进本次任务资料** → 后续文案**结合该热点** |

热点**不是一次性用完就丢**，它沉淀进任务资料。

## 7. 已知要一起修的 bug

| # | Bug | 机制（已定位） |
|---|---|---|
| 1 | **交付卡带着上一轮内容跟到新消息** | `#draft-card` / `#candidate-board` / `#image-results` 是**共享 DOM 节点被移动**，重渲染只在对应工具被调用时才发生 → 旧内容跟着走 |
| 2 | **旧图片/型号 pill 重复出现** | 大概率是 #1 的同一根因 |
| 3 | 图片令牌过期 | **已修**（TTL 30 分钟→12 小时、上限 60→400） |

## 8. 不变的原则（不能因为改流程而丢）

- 产品事实**只读知识库**，保留"约/最高/选配"等限定，不得用记忆覆盖
- 创意自由但**事实不编造**
- **预算耗尽报「部分交付」**（`STATUS_PARTIAL`），不报"完成"
- 交付面规格由 `surface_directive` 注入；**用户明确要求的字数优先于规格**
- 未验证就标 `unverified`，拿不到就说拿不到
