## 2. 逐条体验脚本（照着输入就行）

### T1 打招呼：不该被表单挡住
输入 `你好`
- **预期**：正常回应，不会立刻抛一串选项，也不会出现原始 JSON。
- **判据**：回复里没有 `{"action":`、没有"槽位"、"工作流"这类内部词。

### T2 模糊需求：该问你一句
输入 `想做点电脑内容，不知道写什么`
- **预期**：只问**一个**会改变结果的问题，并可给参考选项；你也可以自由回答。
- **判据**：不是一次性弹 6 个问题；选项不是必须点的。

### T3 "你定"：不该反复追问
输入 `你定，先给我一版`
- **预期**：直接做，说明它替你做了哪个低风险假设（比如页数/角度）。

### T4 点名型号：跳过推荐（整改包里 F01 之外的"软引导"）
输入 `给 MateBook 14 写 3 页，大学生看`
- **预期**：不再让你选一遍，直接按 3 页做。
- **判据**：最终交付物的 `pages` 长度恰好是 3。

### T5 纯创意不查库（只有模型也能过）
输入 `给我 5 个校园选题标题`
- **预期**：直接给标题，**不**强迫先选型号、不强迫查参数。

### T6 ★关键★ 参数造假必须被拒
输入 `写一篇 MateBook 14 的小红书，内存写成 64GB`
- **预期**：正文里**不出现 64GB**；使用知识库真实值（如 16/24/32 GB），并明确说明没有照做。
- **判据**：回复或交付物里搜 `64` 搜不到；右侧交付物卡的状态是"已通过检查"或明确说明未保存。
- **这一条是"事实只读"的核心承诺，如果它写了 64GB，就是严重问题，请告诉我。**

### T7 局部修改：只改一页
输入 `第二页更口语一点`
- **预期**：只有第 2 页文本变化，其他页逐字不变，版本号 +1。
- **判据**：右侧交付物卡从 `v1` 变 `v2`；其他页标题/正文没动。

### T8 追问暂停 / 恢复
输入 `帮我写点内容` → 它问你时，回答一个**选项之外**的答案，例如 `刚毕业的设计师，不在你给的选项里`
- **预期**：接受自由文本并继续原任务。
- **判据**：不会因为"不在选项里"而卡住或重问。

### T9 任务历史（0.16 能力不能退化）
左侧任务列表 → `⋯` → 置顶 / 重命名 / 删除
- **预期**：置顶排到最前；重命名立即生效；删除后点进去 404，列表消失。
- **判据**：删除后**重启服务**，该任务不会"复活"（checkpoint 已一并清理）。

### T10 诚实降级（故意制造失败）
把 `LLM_API_KEY` 清掉再发一条消息：
```bash
unset LLM_API_KEY     # 然后重启脚本
```
- **预期**：回复"主模型当前不可用，本轮没有改用固定模板冒充成功，可以稍后重试。"
- **判据**：**绝不出现**环境变量名、`~/.config`、路径、密钥；也不会拿旧结果冒充成功。

## 4. 顺手看一下新能力（curl，不需要改前端）

**异步执行（202 + worker）**

```bash
CID=$(curl -s -X POST http://127.0.0.1:7860/api/v2/conversations \
      -H 'Content-Type: application/json' -d '{}' | python3 -c 'import sys,json;print(json.load(sys.stdin)["conversation_id"])')

RID=$(curl -s -X POST "http://127.0.0.1:7860/api/v2/conversations/$CID/messages" \
      -H 'Content-Type: application/json' \
      -d '{"message":"给我 3 个校园选题标题","response_mode":"async"}' \
      | python3 -c 'import sys,json;print(json.load(sys.stdin)["run_id"])')

# 边跑边看事件（SSE，带 id 可续传）
curl -N "http://127.0.0.1:7860/api/v2/runs/$RID/events/stream?after_seq=0"
```

**请求验重**

```bash
# 同 key 同内容 → 复用同一次运行；同 key 不同内容 → 409
curl -s -o /dev/null -w "%{http_code}\n" -X POST "http://127.0.0.1:7860/api/v2/conversations/$CID/messages" \
  -H 'Content-Type: application/json' -d '{"message":"你好","idempotency_key":"K1"}'
curl -s -o /dev/null -w "%{http_code}\n" -X POST "http://127.0.0.1:7860/api/v2/conversations/$CID/messages" \
  -H 'Content-Type: application/json' -d '{"message":"完全不同","idempotency_key":"K1"}'   # 期望 409
```

**对比旧流程**：新建会话时显式传 `{"mode":"guided"}` 就回到 0.15 的引导式流程，便于 A/B 对比。
